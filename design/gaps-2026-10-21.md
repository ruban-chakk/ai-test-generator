# Current Product Gaps

**Assessment date:** 2026-10-21
**Scope:** Remaining work after implementation of the core generation workflow, impact analysis, and the three-mode Search page.

## Current baseline

The primary product workflow is implemented. The application can ingest requirements, generate and review test cases, approve and index test cases, run impact analysis, and search project knowledge through semantic, keyword, or hybrid search.

The dedicated Search page now provides:

- semantic, keyword, and hybrid modes;
- keyword search across requirements, approved test cases, and feedback;
- hybrid ranking using reciprocal-rank fusion;
- project and artifact-type filters; and
- component-level ranking evidence in the results.

Live LLM connectivity is verified. Pinecone credentials and the control plane are reachable, but the configured
`ai-testgen-embeddings-vectors` index uses a document schema and cannot accept this application's raw vector
upserts. The application now detects and reports that mismatch before live workflow acceptance creates data. The
remaining work is concentrated in vector lifecycle automation, production validation,
retrieval quality, and impact-analysis calibration.

## Detailed gaps

### 1. Historical data ingestion and vector lifecycle

- Historical test-case JSON/CSV import is available in the Operations page and API. Referenced requirements must be imported first.
- `scripts/backfill_vectors.py` safely recreates missing requirement, feedback, approved-case, and immutable-version outbox intents; `--all` supports deliberate full re-indexing after index replacement.
- Every newly approved or historically imported test-case version is indexed from its immutable PostgreSQL snapshot with a stable versioned vector ID.
- Requirements now retain immutable version snapshots. Jira content changes increment the version and queue a stable `requirement:<id>:v<version>` vector instead of overwriting history.
- Reconciliation is operator-triggered; there is no scheduled drift detector or Pinecone orphan-vector cleanup.

### 2. Search and RAG

The earlier keyword-and-hybrid-search feature gap is closed for the dedicated Search page. The following limitations remain:

- Test-generation RAG still retrieves semantic Pinecone context only; it does not use keyword or hybrid retrieval.
- Keyword search does not index individual test-case steps or scenario content. It searches requirement fields, approved test-case metadata/content, and feedback.
- Search has no typo tolerance, synonym expansion, fuzzy matching, or language-specific stemming.
- Reciprocal-rank fusion uses a fixed configuration that has not been tuned using real relevance judgments.
- Hybrid search does not automatically fall back to keyword-only results when semantic infrastructure is unavailable.
- A search returns at most 50 results and does not support pagination.
- Displayed relevance percentages are ranking indicators, not calibrated probabilities.
- There are no search analytics, click-feedback signals, saved searches, or relevance-evaluation dashboards.

### 3. Generation pipeline

- Generation retrieves semantic context only; keyword and hybrid context are not used.
- Large requirements are not divided into smaller chunks before retrieval or generation.
- Retrieved results are not passed through a reranker.
- Retrieved requirements, test cases, and feedback are not weighted differently by source type.
- Repeated generation returns existing scenarios instead of presenting an explicit regenerate-or-replace workflow.
- Generated test-case quality has not been evaluated against a real labeled enterprise dataset.

### 4. Impact analysis

- Only approved test cases that were successfully indexed participate in impact analysis.
- The default duplicate threshold of `0.80` and update threshold of `0.45` still need calibration against real duplicate, update, and unrelated examples.
- Deprecation detection relies partly on a conservative keyword heuristic.
- Risk and coverage scores are heuristic rather than statistically validated.
- Impact analysis cannot compare a new requirement against immutable, independently indexed historical requirement versions.

### 5. Production acceptance and operations

- A repeatable live workflow acceptance command now covers authentication, requirement creation and indexing, live generation, approvals, approved-case indexing, and impact analysis.
- The live LLM probe is healthy. The current Pinecone index is incompatible because it has a document schema; this app requires a dense bring-your-own-vectors index with 1536 dimensions for `text-embedding-3-small`.
- The complete live workflow remains uncertified until `PINECONE_INDEX_NAME` and `PINECONE_HOST` point to a compatible index and the workflow command succeeds.
- Jira, OIDC, test-repository, execution-runner, and alert integrations still require live tenant acceptance when enabled.
- A local bounded liveness load gate passed 1,000/1,000 requests with 0 failures, 660.37 requests/second, 58.28 ms p50, 124.97 ms p95, and 136.92 ms p99.
- A guarded local PostgreSQL backup/restore drill passed, restoring 26 tables at Alembic revision `20261021_0010` into a disposable database.
- Representative authenticated-query load, soak, fault-injection, external recovery, and Pinecone cost tests remain.
- Database migration `20261021_0010` (which includes the earlier search and historical-import migrations) must be applied in every deployed environment before using immutable requirement and test-case version vectors.

### 6. Workspace state

- The hybrid-search, Pinecone validation, historical import/backfill, and live acceptance changes are currently uncommitted and unpushed.
- The pre-existing untracked `.postqode/` and `scripts/` directories should be reviewed separately before any broad commit operation.

## Recommended implementation order

1. Build and label a representative impact-analysis evaluation set, calibrate thresholds and scoring, and retain the resulting evidence.
2. Create/select the required raw-vector Pinecone index, update its name and host, then run and record a complete real-data end-to-end acceptance test.
3. Extend generation retrieval to hybrid search, then improve search coverage, fallback behavior, pagination, and relevance measurement.
4. Add scheduled vector drift detection and Pinecone orphan cleanup.

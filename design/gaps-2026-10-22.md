## Remaining validation gaps

### Supplied dataset readiness

The supplied files contain 190 stories and 6,354 source test cases. They reference 109 story keys that are absent;
1,812 test cases have at least one resolvable story and 4,542 have none. With the recommended `stage` policy, the
formerly skipped 10,900 expanded test-case/story relationships are preserved in the unresolved queue instead of
being discarded. They become normal approved/versioned/indexed cases automatically after the missing stories are
imported. The source organization still needs to supply those 109 stories or explicitly dismiss the staged links.

### 1. Tenant-labeled retrieval and impact calibration

No representative enterprise-labeled dataset has been supplied. The app provides the collection and calibration
mechanisms, but the following cannot honestly be certified from synthetic examples:

- generated test quality against company expectations;
- optimal semantic/keyword/source weights and RRF constant;
- duplicate/update thresholds for the tenant's terminology;
- statistical validity of risk, coverage, and deprecation recommendations; and
- multilingual relevance quality.

Required input: anonymized requirements, approved tests, relevance judgments, expected impact actions, and a review
rubric. Apply the resulting thresholds only after holding out a separate validation set.

### 3. Production operational certification

The local automated gates are green, but the target deployment still needs:

- authenticated API load, soak, and concurrency testing using production-like volumes;
- failure injection for LLM, Pinecone, PostgreSQL, and worker restarts;
- target-environment backup/restore and recovery-time evidence;
- alert, log, metric, and retention integration with the company's observability stack;
- Pinecone billing-budget alerts (the application reports counts and estimated dense-vector bytes, not provider billing); and
- security/privacy review for real company data and retention requirements.

### 4. Known bounded behavior

- Streamed resumable JSON requires a top-level array. Nested `record_path` documents use the bounded preview/import
  path; export nested sources as JSONL for very large jobs.
- Fuzzy keyword matching uses PostgreSQL `pg_trgm` and English stemming. Other languages need a project-specific
  text-search configuration or external search engine.
- The visual custom-field builder covers common type/required/index/weight settings. Advanced enum, regex, default,
  and length rules remain available through the advanced JSON editor.
- Pinecone orphan deletion is intentionally disabled by default and allowed only for a full namespace audit.
